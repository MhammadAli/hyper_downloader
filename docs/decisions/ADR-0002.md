# ADR-0002: Adopting `MediaExtractorBackend` with `yt-dlp` for Media Inspection, Format Discovery, and Stream Muxing

- **Status:** Proposed (Phase 0 Revised Architecture Review)
- **Date:** 2026-11-18
- **Supersedes:** Decision 4 of [ADR-0001](./ADR-0001.md) (Official YouTube Data API v3 metadata-only boundary)
- **Decision Drivers:** Support URL-based media downloading from publicly accessible videos and authorized media sources, genuine dynamic format discovery, FFmpeg stream merging, playlist enumeration, Android 15+ 16 KB page-size compliance, and avoiding custom YouTube extractor maintenance in Rust.

---

## Context

The initial Phase 0 ADR (`ADR-0001` Decision 4) scoped YouTube integration strictly to YouTube Data API v3 metadata and owner captions. Following product scope clarification, HyperDownload's core purpose requires URL-based media downloading of publicly accessible videos and authorized media sources—discovering genuine available formats, selecting single or separate audio/video streams (`DownloadFormatChoice`), muxing via FFmpeg when needed, and managing playlists cleanly.

Reimplementing YouTube extraction in Rust is high-risk and brittle because media platforms rotate player JavaScript, signature ciphers, and `n`-challenges continuously. Conversely, letting `yt-dlp` take over job queuing, deduplication, or SQLite persistence would couple HyperDownload to a monolithic CLI wrapper and compromise direct HTTP byte-range file downloads.

---

## Decisions

### 1. Introduce an Independent `MediaExtractorBackend` Trait (`rust/crates/extractor_backend`)
- Define a backend-agnostic `MediaExtractorBackend` abstraction inside `rust/crates/extractor_backend`.
- Implement `providers/yt_dlp` against `provider_api::MediaProvider` and `MediaExtractorBackend`, delegating extraction, format discovery, playlist enumeration, adaptive DASH/HLS transfer, and FFmpeg stream muxing to `yt-dlp`.
- Keep generic HTTP/HTTPS file downloads (`providers/direct_http` + `download_core`), job scheduling (`download_queue`), and SQLite persistence (`persistence`) completely modular and independent from `yt-dlp`.

### 2. Dual Download Execution Path Under `download_queue` with Separated Resume State
- `download_queue` owns concurrency limits, FIFO priority, `DownloadFormatChoice`-based deduplication, continuous SQLite checkpoints, and throttled `StreamSink` progress events for **all** jobs.
- Execution routes cleanly by provider:
  - **Direct HTTP (`ProviderId::DirectHttp`):** Executed by Rust's `download_core` using `ExecutionResumeState::DirectHttp(HttpResumeState)` (`206 Partial Content`, `If-Range`, `ETag`).
  - **Extractor-Backed (`ProviderId::YtDlp`):** Executed by `MediaExtractorBackend::execute_download` using `ExecutionResumeState::Extractor(ExtractorStagingState)` (`DownloadingPrimaryStream -> DownloadingSecondaryAudioStream -> MergingStreams`), ensuring extractor `.part`/component staging never mixes with HTTP range state.

### 3. Platform-Specific `yt-dlp`, EJS JS Runtime, and Android Execution Bridge Strategy
- **Windows:** Execute standalone `yt-dlp.exe` (bundling Python `3.11+` and `yt-dlp-ejs`) stored in `%LOCALAPPDATA%\HyperDownload\bin\`, paired with an external EJS JavaScript runtime (**Deno `>= 2.3.0`**, **Node.js `>= 22.0.0`**, or **QuickJS `>= 2025-4-26`**) and external `ffmpeg.exe` (`--ffmpeg-location`). Host Python 3.9 is intentionally bypassed.
- **Android:** Use **Chaquopy `17.2.0` (`>= 16.0.0`, MIT)** embedding **Python `3.13`** (matching host `buildPython 3.13.x`) installing **`yt-dlp` + `yt-dlp-ejs` + `certifi`** (excluding GPL-2.0+ `mutagen`), paired with 16 KB page-aligned PIE binaries **`libqjs.so` (QuickJS `>= 2025-4-26`, MIT)** and **`libffmpeg.so` / `libffprobe.so` (LGPL build recommended)** in `jniLibs/<abi>/` (`android:extractNativeLibs="true"`, `useLegacyPackaging = true`, symlinked into `<filesDir>/bin`).
- **Android Execution Bridge & Continuous Recovery:** Rust connects to Kotlin via a lightweight JNI module inside `engine_ffi` (`NativeEngineJni` / `AndroidPlatformBridge`), allowing `HyperDownloadJobService` (UIDT API 34+) to drive the Rust queue headlessly even when Flutter UI is closed. Both Rust `download_core` and `yt-dlp` persist durable SQLite checkpoints continuously (every 1 s / 1 MiB + phase transitions) rather than relying on `JobService.onStopJob()` alone, enabling safe recovery after abrupt `SIGKILL` termination.
- *(Alternative Note: `io.github.junkfood02.youtubedl-android:0.18.1` is rejected as default due to its **GPL-3.0** license, remaining documented only if the project explicitly opts into GPL-3.0.)*

### 4. Strict Security, Anti-Circumvention & Legal Terminology Guardrails
- Target only publicly accessible, unauthenticated media and explicitly authorized sources.
- Never pass `--cookies`, `--cookies-from-browser`, login credentials, or bypass logic for private, members-only, paywalled, or DRM-protected streams (`BlockedDrmOrAccessRestricted`).
- Name format availability variants strictly (`DiscoveredSingle`, `DiscoveredRequiresMuxing`) and explicitly state in UI and docs that technical format discovery is not proof of legal authorization to download.

---

## Consequences

### Positive
- Delivers genuine dynamic format discovery, playlist enumeration, and FFmpeg stream muxing across Windows and Android without writing custom extraction logic in Rust.
- Eliminates duplicating `yt-dlp`'s DASH/HLS fragment downloader while preserving clean HTTP range downloads, continuous SQLite crash recovery, and headless Android UIDT background execution.
- Android packaging preserves permissive licensing (Chaquopy MIT, QuickJS MIT, `yt-dlp`/`yt-dlp-ejs` Unlicense, LGPL FFmpeg CLI) and meets Android 15+ 16 KB ELF page-alignment requirements.

### Negative & Mitigations
- **Build & Packaging Complexity on Android:** Requires Windows host Python `3.13` (`buildPython`), `useLegacyPackaging = true`, `<filesDir>/bin` symlinks for `ffmpeg`, and NDK r28+ 16 KB alignment verification. *Mitigation:* Isolated and validated upfront in Phase 3 before building Phase 4 product features.
- **Bundled Dependency & Licensing Hygiene:** Official PyInstaller `yt-dlp.exe` includes `mutagen` (GPL-2.0+). *Mitigation:* Android explicitly excludes `mutagen` in Chaquopy `pip`; Windows either installs `yt-dlp.exe` via user-initiated runtime download or provides full GPL/LGPL/MIT/Unlicense attribution notices in Settings.
